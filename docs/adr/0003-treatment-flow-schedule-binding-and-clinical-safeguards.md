# 3. สถาปัตยกรรมเวชระเบียนแบบสถานีเดียว ความปลอดภัยของข้อมูลยา และการผูกตารางเวรแพทย์ (Single-Station Clinical Flow, Medicine Safety & Schedule Binding)

## Context

จากการทดสอบระบบจริง (User Acceptance Testing) พบจุดปรับปรุงเชิงสถาปัตยกรรมและกระบวนการทำงานหลัก 4 ด้าน:
1. **การบันทึกการรักษาเคส Walk-in และตารางเวลาแพทย์**: เดิมระบบแก้ปัญหาเคส Walk-in โดยการแอบ auto-generate ตารางเวรและสร้างสล็อตเวลา 30 นาทีในเบื้องหลัง ทำให้สถิติชั่วโมงการทำงานของแพทย์และตารางนัดหมายไม่สอดคล้องกับความเป็นจริง
2. **ความปลอดภัยของคลังยา (Medicine Catalog Integrity)**: เดิมระบบมีปุ่ม Hard Delete ซึ่งหากยาเคยถูกสั่งจ่ายในเวชระเบียนหรือมีล็อตสต็อกแล้ว จะทำให้เกิดข้อผิดพลาด Foreign Key Constraint หรือประวัติเวชระเบียนย้อนหลังเสียหาย
3. **การไหลของงานตรวจรักษาและการเงิน (Clinical vs Billing Flow)**: มีการพิจารณาแยกระหว่าง "ห้องตรวจแพทย์" และ "ห้องจ่ายยา/การเงิน" (Two-station Flow) หรือคงไว้เป็นสถานีเดียว (Single-station Flow)
4. **ความสมบูรณ์ของเวชระเบียนหลังออกใบเสร็จ (Financial Lockdown)**: เดิมสามารถกลับมาแก้รายการยาได้แม้จะออกใบเสร็จรับเงินไปแล้ว ซึ่งเสี่ยงต่อการทุจริตหรือยอดสต็อก/ยอดเงินไม่ตรงกับรายงานบัญชี

## Decision

1. **คงสถาปัตยกรรม Single-station Flow (ตรวจรักษา สั่งยา คิดเงิน จบในหน้าเดียว)**:
   - เหมาะสมกับรูปแบบคลินิกแพทย์แผนไทยในปัจจุบันที่แพทย์เป็นผู้ตรวจ วินิจฉัย สั่งยา และสรุปยอดค่าบริการด้วยตนเอง
   - ปรับปรุงจุดบกพร่องเรื่องการค้นหายา: แทนที่ Dropdown `<select>` เดิมด้วย **Searchable Combobox** ที่สามารถพิมพ์ค้นหาชื่อยา/รหัสยา/สรรพคุณได้ทันที พร้อมแสดงป้ายหมวดหมู่ ราคา และยอดคงเหลือปัจจุบัน
2. **นโยบายระงับการจำหน่ายยาแทนการลบ (Soft Delete via `isActive`)**:
   - เพิ่มฟิลด์ `is_active` (boolean) ในตาราง `Medicine`
   - เมื่อแพทย์กดยกเลิกใช้งานยา ระบบจะไม่ลบแถวข้อมูลออกจากฐานข้อมูล เพื่อรักษาประวัติการสั่งจ่ายในอดีต บัญชีคุมคลังสะสม และเอกสารใบเสร็จให้ยังอ้างอิงได้ถูกต้อง
   - ยาที่ `isActive = false` จะถูกกรองออกจากการสั่งจ่ายใหม่และการรับสต็อกเข้า
3. **การผูกการรักษาเข้ากับสล็อตตารางเวรจริง (Mandatory Scheduled Slot Binding)**:
   - ยกเลิกการ auto-generate ตารางเวรและสล็อตจำลองเบื้องหลังทั้งหมด
   - การบันทึกเวชระเบียน (ทั้งเคสนัดหมายและเคส Walk-in) จะต้องเลือกสล็อตเวลาที่มีแพทย์เปิดตารางเวร (Working Schedule) อยู่จริงเท่านั้น
   - หากแพทย์ยังไม่ได้กำหนดเวลาปฏิบัติงานในวันนั้น ระบบจะปฏิเสธการบันทึกและแจ้งเตือนให้แพทย์ไปจัดตารางเวรก่อน
4. **การล็อคเวชระเบียนหลังออกใบเสร็จ (Receipt Issued Lockdown)**:
   - เมื่อมีการออกใบเสร็จรับเงิน (`Receipt`) สำหรับการรักษานั้นแล้ว ระบบจะล็อครายการยาสมุนไพรและรายการค่าบริการทางการเงินทั้งหมด (ห้ามเพิ่ม ลบ หรือแก้ไขจำนวน/ราคา)
   - ยังอนุญาตให้แพทย์แก้ไขเพิ่มเติมบันทึกคำแนะนำ (Suggestions) และผลการประเมินอาการเพื่อประโยชน์ในการติดตามผลการรักษาได้
5. **ปฏิทินนัดหมาย 7 วันแบบตารางเวลา (Weekly Calendar Grid View)**:
   - พัฒนามุมมองตาราง 7 วัน (จันทร์-อาทิตย์, แกนเวลา 08:00 - 19:00 น., แถวละ 1 ชั่วโมง) ตามแบบ Google Calendar
   - รองรับการคลิกที่ช่องว่างของวัน/เวลาเพื่อเปิด Modal ทำการนัดหมายคนไข้ได้ทันทีโดยแพทย์
6. **ระบบแจ้งเตือนผู้ป่วย (Notification Bell with 3-Day Advance Reminder)**:
   - แสดงไอคอนกระดิ่งและเลขอ่านค้างบน Navbar ผู้ป่วย
   - แจ้งเตือนสถานะนัดหมาย (อนุมัติ, เลื่อน, ยกเลิก) และเตือนล่วงหน้าอย่างน้อย 3 วันก่อนถึงเวลานัดทุกครั้งที่เข้าสู่ระบบ
   - แจ้งเตือนเมื่อตรวจเสร็จและมีใบสั่งยา/ใบเสร็จรับเงินพร้อมตรวจสอบ

## Consequences

- **ข้อดี**: 
  - ความถูกต้องของข้อมูลทางบัญชีและสต็อกยา 100%
  - สถิติชั่วโมงการทำงานของแพทย์สอดคล้องกับตารางเวรจริง
  - ประสบการณ์การทำงานของแพทย์รวดเร็วขึ้นผ่าน Searchable Combobox และปฏิทินรายสัปดาห์
  - ผู้ป่วยได้รับข้อมูลที่ชัดเจน เข้าใจง่าย และไม่พลาดนัด
- **สิ่งที่ต้องปรับเปลี่ยน (Schema & Code Impacts)**:
  - เพิ่มคอลัมน์ `is_active` ใน Entity `Medicine` และ DTOs
  - อัปเดต `AppointmentController` และ `AppointmentService` ให้รองรับ Role `DOCTOR` สามารถจองคิวนัดหมายได้
  - สร้างตาราง `patient_notifications` หรือเซอร์วิสคำนวณการแจ้งเตือนสำหรับผู้ป่วย
