# 1. สถาปัตยกรรมการจัดการคลังยาสมุนไพร ล็อตยา และวันหมดอายุ (Medicine Lot & Expiry Architecture)

## Context

ระบบเดิมออกแบบตามเอกสาร SRS v3.2 โดยอ้างอิงจากแบบฟอร์มกระดาษ "บัญชีคุมคลังยา/สต็อกการ์ด" ทำให้ในตาราง `medicine` มีฟิลด์ `stock_brought_forward` (ยอดยกมา), `stock_received` (รับเข้า), `stock_issued` (จ่ายออก), และ `stock_remaining` (คงเหลือ) รวมอยู่ในตารางหลักของรายการยา

ปัญหาที่พบจากการใช้งานจริงคือ:
1. ขาดข้อมูล **เลขล็อต (Lot Number)** และ **วันหมดอายุ (Expiry Date)** ซึ่งเป็นสิ่งสำคัญอย่างยิ่งในการบริหารจัดการยาสมุนไพรทางการแพทย์แผนไทย เพื่อป้องกันการจ่ายยาหมดอายุให้แก่คนไข้
2. หน้าจอเดิมมีเพียงปุ่ม "แก้ไขยา" และให้ผู้ใช้พิมพ์ตัวเลข `stock_remaining` ทับลงไปตรงๆ ทำให้ค่า `stock_received` และ `stock_issued` ไม่สอดคล้องกัน ($0 + 100 - 0 \neq 20$) และขาดขั้นตอนการ "รับยาเข้าคลัง"
3. ตัวเลือกหมวดหมู่ยาบนหน้าบ้านถูกกำหนดไว้ตายตัว (Hardcoded 6 หมวดหมู่) ไม่ยืดหยุ่นและไม่สะท้อนการจำแนกตำรับยาแผนไทยจริง

## Decision

1. **เพิ่ม Entity `MedicineLot` (ตาราง `medicine_lots`)**: เชื่อมโยงแบบ One-to-Many กับ `Medicine` เพื่อเก็บประวัติการรับยาเข้าแต่ละรุ่น ประกอบด้วย `lot_number`, `expiry_date`, `manufacture_date`, `received_date`, `quantity_received`, `quantity_remaining`, `cost_price`, `status`, และ `note`
2. **รักษาฟิลด์เดิมใน `Medicine` แบบ Automated Ledger**: คงคอลัมน์ `stock_brought_forward`, `stock_received`, `stock_issued`, `stock_remaining` ในตาราง `medicine` ไว้ตาม SRS v3.2 เพื่อความเข้ากันได้ย้อนหลัง (Backward Compatibility) แต่ไม่อนุญาตให้แก้ไขด้วยมือผ่านฟอร์ม โดยระบบจะคำนวณและอัปเดตให้อัตโนมัติ:
   - `stock_received`: ผลรวมยอดรับเข้าสะสมจากการบันทึกรับล็อตยา
   - `stock_issued`: ผลรวมยอดจ่ายสะสมจากการสั่งจ่ายยาในห้องตรวจรักษา
   - `stock_remaining`: ผลรวมยอดคงเหลือจริงจากทุกล็อตที่ยังไม่หมดอายุ
3. **ปรับเวิร์กโฟลว์หน้า UI (Frontend UX)**: แยก 3 การกระทำ (Actions) ชัดเจน:
   - **รับยาเข้าคลัง / เพิ่มล็อตใหม่ (+ Receive Stock)**: บันทึกเลขล็อต วันหมดอายุ จำนวนรับเข้า
   - **ปรับปรุงสต็อก (Stock Adjustment)**: ปรับยอดนับจริง ยาแตกหัก เสียหาย หรือตัดจำหน่ายยาหมดอายุ พร้อมระบุเหตุผล
   - **แก้ไขข้อมูลยา (Edit Medicine Info)**: แก้ไขเฉพาะชื่อยา หมวดหมู่ ราคาขาย หน่วยนับ และสรรพคุณ
4. **หมวดหมู่ยาแบบยืดหยุ่น (Datalist / Creatable)**: ใช้ชุดหมวดหมู่แนะนำตามศาสตร์การแพทย์แผนไทย (ยาเดี่ยว, ยาตำรับ, ยาประจุล/ภายนอก, ลูกประคบ/น้ำมัน, ชาชง, เวชภัณฑ์) พร้อมเปิดให้ผู้ใช้พิมพ์หมวดหมู่ใหม่ได้อิสระ และระบบจะดึงหมวดหมู่ที่มีอยู่จริงมาสร้างตัวกรองอัตโนมัติ
5. **การตัดสต็อกอัตโนมัติแบบ FIFO (Earliest Expiry First)**: เมื่อแพทย์สั่งจ่ายยา ระบบจะตัดจากล็อตที่หมดอายุก่อนอัตโนมัติ และบันทึก `lot_id` ลงใน `record_treatment_medicines` หากจ่ายข้ามล็อต จะทำการแยกบันทึกตามล็อตจริงเพื่อการตรวจสอบย้อนกลับ (Traceability)
6. **ระบบป้องกันยาหมดอายุ (Expiry Guardrails)**: แสดงป้ายเตือนและตัวกรองยาใกล้หมดอายุ (ภายใน 30-60 วัน) และ **บล็อกการสั่งจ่ายยาที่หมดอายุแล้วในระบบตรวจรักษาโดยเด็ดขาด**

## Considered Options

- **Option A (ที่เลือก)**: แยกตาราง `MedicineLot` พร้อมรักษาสมดุลกับ SRS v3.2 ด้วย Automated Ledger
- **Option B (คงตารางเดิมและเพิ่มแค่ฟิลด์วันหมดอายุใน `Medicine`)**: ถูกปฏิเสธ เนื่องจากไม่สามารถรองรับการมียาล็อตเดิมเหลืออยู่และมีล็อตใหม่เข้ามาเสริมได้ ขัดต่อกระบวนการคลังยาจริง
- **Option C (ลบฟิลด์ `stock_brought_forward`, `stock_received`, `stock_issued` ออกทั้งหมด)**: ถูกปฏิเสธ เนื่องจากจะกระทบต่อ Data Dictionary เดิมในเล่มรายงานโครงงานของมหาวิทยาลัยโดยไม่จำเป็น
