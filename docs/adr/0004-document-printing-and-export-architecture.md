# 4. สถาปัตยกรรมการพิมพ์เอกสารคลินิก การจัดการไฟล์ Word และการถอด JasperReports (Clinical Document Printing, Word Export & Sunsetting JasperReports)

## Context

ระบบบริหารจัดการคลินิกมีเอกสารทางคลินิกและเอกสารการเงินที่ต้องส่งออก (Export) และพิมพ์ (Print) รวม 5 หมวดหลัก:
1. **บัตรเวชระเบียนผู้ป่วยนอก (OPD Card)**
2. **แบบกรอกประวัติผู้ป่วย (Patient Registration Form - Thai / English)**
3. **แบบบันทึกข้อมูลผู้รับบริการ (Client Intake Form)** ซึ่งแบ่งเป็น 2 กรณี: ผู้ป่วยมาครั้งแรก (First Visit - 4 หน้า) และ ผู้ป่วยรักษาต่อเนื่อง (Continued Treatment - 1 หน้า)
4. **ใบสั่งการรักษาและค่าใช้จ่าย (Treatment Order & Billing)**
5. **ใบรับรองแพทย์ (Medical Certificate)** และ **ใบเสร็จรับเงิน (Receipt)**

เดิมระบบประสบปัญหาเชิงสถาปัตยกรรมและประสบการณ์ผู้ใช้งาน:
1. **ปุ่มดาวน์โหลดกระจัดกระจายและซ้ำซ้อน**: ปุ่มดาวน์โหลด Word ถูกนำไปวางไว้ในทุกแถวของตารางรายชื่อผู้ป่วยและตารางประวัติการรักษา ทำให้ UI แน่น รกสายตา และไม่แยกหน้าที่ระหว่างเอกสารระดับผู้ป่วย (Patient Level) กับเอกสารระดับครั้งการรักษา (Treatment Visit Level)
2. **สถาปัตยกรรมการพิมพ์ไม่เป็นหนึ่งเดียวและมี JasperReports ตกค้าง**: มีการดึงไลบรารี `net.sf.jasperreports` มารองรับการพิมพ์ใบเสร็จรับเงินเพียงจุดเดียว (`receipt.jrxml`) ในขณะที่เอกสารอื่นใช้ `poi-tl` ส่งออกเป็น `.docx` ทำให้ระบบ build หนักโดยไม่จำเป็น และไม่มีฟังก์ชันการสั่งพิมพ์ตรงหรือแปลงเป็น PDF สำหรับเอกสารเวชระเบียนอื่นๆ
3. **ปัญหาการแปลง DOCX เป็น PDF สำหรับภาษาไทย**: การแปลงไฟล์ Word (.docx) เป็น PDF บนฝั่ง Backend Java มักพบปัญหาวรรณยุกต์ลอย การตัดคำภาษาไทยตกหล่น หรือต้องพึ่งพาโปรแกรมบุคคลที่สามภายนอก (เช่น Headless LibreOffice) ซึ่งเพิ่มภาระในการดูแลระบบ

## Decision

1. **ถอดถอน JasperReports ออกจากระบบอย่างสมบูรณ์ (Sunsetting JasperReports)**:
   - ลบ dependency `net.sf.jasperreports` ออกจาก `backend/pom.xml`
   - ลบไฟล์เทมเพลต `receipt.jrxml` และปรับปรุง `ReceiptPrintController` / `ReportService` ให้สอดคล้องกับสถาปัตยกรรมใหม่
2. **สถาปัตยกรรมเอกสารสองโหมด (Dual Document Architecture)**:
   - **โหมดสั่งพิมพ์ / บันทึก PDF (Native Browser A4 Print View)**: พัฒนาหน้ารองรับการพิมพ์แยกต่างหากใน Frontend (เปิดในแท็บใหม่ เช่น `/print/...`) จัดรูปแบบเอกสารขนาด A4 ด้วย CSS `@media print` จำลองแบบฟอร์มกระดาษจริงของคลินิกแบบ 1:1 รองรับการสั่งพิมพ์ผ่านหน้าต่างเบราว์เซอร์หรือ "Save as PDF" ได้ทันที โดยตัวอักษรภาษาไทยคมชัด 100% ไม่ผิดเพี้ยน
   - **โหมดดาวน์โหลด Word (.docx via poi-tl)**: ให้บริการสำหรับแพทย์/เจ้าหน้าที่ที่ต้องการนำไฟล์ดิบไปเปิดแก้ไข ปรับปรุงข้อความ หรือจัดหน้าเพิ่มเติมในโปรแกรม Microsoft Word
3. **การแยกเอกสารแบบบันทึกผู้รับบริการ (First Visit vs Continued Treatment)**:
   - **แบบตรวจครั้งแรก (`client_intake_form.docx`)**: ปรับปรุงเหลือ 4 หน้า (ส่วนที่ 1 ถึง ส่วนที่ 5) โดยตัดใบสั่งการรักษาออกไปเป็นเอกสารเดี่ยว
   - **แบบรักษาต่อเนื่อง (`client_intake_continued.docx`)**: สร้างเทมเพลตใหม่ 1 หน้าตามตัวอย่างจริง (สัญญาณชีพ, อาการสำคัญ, Reflex RT/LT, ประวัติปฏิเสธ/มีโรค, การวินิจฉัยธาตุ/รหัสโรค, รายการรักษา, วันนัดครั้งต่อไป)
   - หน้ารายละเอียดการตรวจรักษาจะตรวจจับประวัติของผู้ป่วยและเลือกฟอร์มเริ่มต้นให้อัตโนมัติ พร้อมมี Dropdown ให้แพทย์เลือกสลับฟอร์มได้ตามความประสงค์
4. **การรวมใบสั่งการรักษาและใบเสร็จรับเงินเป็นเอกสารฉบับเดียว (`treatment_order.docx`)**:
   - รวม "ใบสั่งการรักษา" และ "ใบสรุปค่ารักษา/ใบเสร็จรับเงิน" เข้าเป็นเอกสารทางการแพทย์และการเงินฉบับเดียวกัน 1 หน้าตามแบบฟอร์มจริงของคลินิกพิมพ์วิมาน (PDF หน้า 1, 2 และ 5)
   - ประกอบด้วยข้อมูลผู้ป่วย สิทธิการรักษา ตารางรายการหัตถการ ค่าบริการ และยาสมุนไพรที่สั่งจ่าย พร้อมราคาต่อหน่วย จำนวน ค่ารักษา และยอดรวมเงินสุทธิ โดยมีชื่อแพทย์และเลขที่ใบประกอบวิชาชีพกำกับ
   - ให้บริการสั่งพิมพ์ (A4 Print / Save PDF) และดาวน์โหลด Word ได้จากทั้งหน้ารายละเอียดการตรวจรักษา และฝั่งผู้ป่วยสามารถดู/พิมพ์เอกสารยอดค่ารักษานี้ได้
5. **การจัดระเบียบตำแหน่งปุ่มดาวน์โหลด/พิมพ์บน UI (UI Decluttering)**:
   - **หน้ารวมตาราง (List Views)**: ลบปุ่มดาวน์โหลด/พิมพ์ออกจากทุกแถว คงไว้เพียงปุ่ม "ดูรายละเอียด"
   - **หน้าข้อมูลผู้ป่วย (`/doctor/patients/[id]`)**: รวมศูนย์เฉพาะเอกสารระดับผู้ป่วย (OPD Card, แบบกรอกประวัติไทย, แบบกรอกประวัติอังกฤษ)
   - **หน้ารายละเอียดการรักษา (`/doctor/treatments/[id]`)**: รวมศูนย์เฉพาะเอกสารระดับครั้งการตรวจ (แบบบันทึกผู้รับบริการ, ใบสั่งการรักษาและค่าใช้จ่าย, ใบรับรองแพทย์)
   - **แบบฟอร์มเปล่า (Blank Form)**: เพิ่มปุ่มดาวน์โหลด/พิมพ์แบบฟอร์มเปล่าสำหรับผู้ป่วยใหม่ที่หน้าทะเบียนผู้ป่วยและหน้าเพิ่มผู้ป่วยใหม่

## Consequences

- **ข้อดี**:
  - ลดขนาดและภาระของ Backend โดยไม่ต้องแบกรับ dependency ของ JasperReports
  - คุณภาพการพิมพ์เอกสารและการ Save as PDF สวยงาม ฟอนต์ภาษาไทยคมชัด 100% ตรงตามแบบฟอร์มจริงของคลินิก
  - ลดความซ้ำซ้อนของเอกสารการเงิน ไม่ต้องแยกระหว่างใบสั่งยากับใบเสร็จให้สับสน
  - รองรับทั้งผู้ที่ต้องการพิมพ์กระดาษด่วน และผู้ที่ต้องการไฟล์ Word ไปพิมพ์งานต่อ
  - หน้าจอระบบสะอาดตา ไม่สับสน ปุ่มดาวน์โหลดและพิมพ์ถูกจัดวางตรงตามขอบเขตความรับผิดชอบ
- **สิ่งที่ต้องจัดเตรียม**:
  - เทมเพลต Word ทั้ง 7 รายการใน `backend/src/main/resources/templates/`
  - คอมโพเนนต์และ Route สำหรับ A4 Print View ใน Frontend
  - การทำ End-to-end Test ตรวจสอบความถูกต้องของการดึงข้อมูลลงแบบฟอร์ม
