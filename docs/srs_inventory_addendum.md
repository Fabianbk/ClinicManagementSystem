# เอกสารส่วนเพิ่มเติมและบันทึกการปรับปรุงระบบคลังยา (SRS Inventory Addendum & Change Log)

เอกสารฉบับนี้จัดทำขึ้นเพื่อเป็นข้อมูลประกอบการปรับปรุงเอกสารข้อกำหนดความต้องการของระบบ (SRS เวอร์ชัน 3.2) และรายงานปริญญานิพนธ์ (เล่มจบ) สาขาเทคโนโลยีสารสนเทศ คณะวิทยาศาสตร์ มหาวิทยาลัยแม่โจ้

---

## 1. วัตถุประสงค์ของการปรับปรุง (Rationale)

จากการทดสอบการใช้งานระบบจริง พบว่าการบริหารจัดการคลังยาสมุนไพรในรูปแบบเดิมที่อ้างอิงจากแบบฟอร์มกระดาษ (มีเพียงฟิลด์ยอดยกมา รับเข้า จ่ายออก ในระดับรายการยา) ยังไม่ตอบสนองต่อการปฏิบัติงานทางการแพทย์แผนไทยอย่างมีประสิทธิภาพสูงสุด เนื่องจาก:
1. **ขาดการบันทึกเลขล็อต (Lot Number) และวันหมดอายุ (Expiry Date)**: ยาสมุนไพรมีอายุการเก็บรักษาและอาจเสื่อมสภาพได้ การไม่ทราบวันหมดอายุและเลขล็อตเสี่ยงต่อการจ่ายยาเสื่อมคุณภาพให้แก่ผู้ป่วย
2. **ขั้นตอนการทำงานบนระบบไม่สอดคล้องกับความเป็นจริง**: ขาดฟังก์ชันการ "รับยาเข้าคลังแยกตามรุ่นที่ผลิต" และ "การปรับปรุงยอดสต็อกจากการนับจริง"
3. **ความถูกต้องของข้อมูล (Data Integrity)**: การให้ผู้ใช้แก้ไขยอดคงเหลือด้วยมือทำให้ตัวเลขยอดยกมา รับเข้า และจ่ายออกเกิดความขัดแย้งกัน

จึงได้ทำการปรับปรุงสถาปัตยกรรมระบบคลังยา โดยเพิ่มเอนทิตี **ล็อตยา (`MedicineLot`)** รองรับการตัดจ่ายยาตามลำดับวันหมดอายุ (FIFO) และระบบป้องกันการจ่ายยาหมดอายุ พร้อมรักษาความเข้ากันได้กับฐานข้อมูลเดิม

## 2. การปรับปรุงรายละเอียดของยูสเคส (Use Case Specifications)

### 2.1 ปรับปรุง ยูสเคส 3.1.30: Add Medicine / Receive Stock (เพิ่มยาและรับยาเข้าคลัง)
* **คำอธิบาย**: แพทย์สามารถลงทะเบียนตำรับยาใหม่ พร้อมทั้งบันทึกการรับยาสมุนไพรเข้าคลังเป็นล็อต (Lot) โดยระบุเลขล็อต วันที่ผลิต วันหมดอายุ จำนวนรับเข้า และราคาทุน
* **ความต้องการของระบบเพิ่มเติม**:
  * **เลขล็อต (lotNumber)**: ความยาวไม่เกิน 50 ตัวอักษร, ต้องไม่เป็นค่าว่าง
  * **วันหมดอายุ (expiryDate)**: ต้องเป็นวันที่ในอนาคต, รูปแบบ YYYY-MM-DD
  * **จำนวนรับเข้า (quantityReceived)**: ตัวเลขจำนวนเต็มมากกว่า 0

### 2.2 ปรับปรุง ยูสเคส 3.1.31: List All Medicine & Lots (แสดงรายการคลังยาและล็อตยา)
* **คำอธิบาย**: แสดงรายการยา สรรพคุณ ราคาขาย ยอดคงเหลือรวม พร้อมสถานะแจ้งเตือน:
  * **ปกติ (Normal)**: ยามีจำนวนเพียงพอและยังไม่ใกล้หมดอายุ
  * **ยาใกล้หมด (Low Stock)**: ยอดคงเหลือ $\le$ 20 หน่วย
  * **ยาใกล้หมดอายุ (Expiring Soon)**: ล็อตยาจะหมดอายุภายใน 30-60 วัน (ป้ายเตือนสีส้ม)
  * **ยาหมดอายุ (Expired)**: ล็อตยาที่พ้นกำหนดวันหมดอายุ (ป้ายเตือนสีแดง และบล็อกการสั่งจ่าย)

### 2.3 ปรับปรุง ยูสเคส 3.1.32: Edit Medicine & Stock Adjustment (แก้ไขข้อมูลยาและปรับยอดสต็อก)
* **คำอธิบาย**: แยกการทำงานเป็น 2 ส่วน:
  1. **แก้ไขข้อมูลทั่วไปของยา**: ชื่อยา หมวดหมู่ ราคาขาย หน่วยนับ สรรพคุณ
  2. **การปรับปรุงยอดสต็อก (Stock Adjustment)**: ปรับยอดคงเหลือเมื่อตรวจนับจริงไม่ตรง หรือตัดจำหน่ายยาชำรุด/แตกหัก/หมดอายุ พร้อมบันทึกเหตุผลกำกับ

## 3. การปรับปรุงคลาสไดอะแกรม (Class Diagram Specifications)

### 3.1 คลาสใหม่: ล็อตยา (`MedicineLot`)
* **`lotId`** : `int` (PK) - รหัสประจำตัวล็อตยา
* **`medicineId`** : `int` (FK) - รหัสยาที่อ้างอิง
* **`lotNumber`** : `String` - เลขล็อต / เลขที่รุ่นการผลิต
* **`manufactureDate`** : `Date` - วันที่ผลิตยา
* **`expiryDate`** : `Date` - วันหมดอายุของยา
* **`receivedDate`** : `Date` - วันที่รับยาเข้าคลัง
* **`quantityReceived`** : `int` - จำนวนที่รับเข้ามาในล็อตนี้
* **`quantityRemaining`** : `int` - จำนวนที่คงเหลืออยู่ในล็อตนี้
* **`costPrice`** : `Double` - ราคาทุนต่อหน่วย
* **`status`** : `String` - สถานะล็อตยา (`ACTIVE`, `DEPLETED`, `EXPIRED`)
* **`note`** : `String` - หมายเหตุเพิ่มเติม

### 3.2 ความสัมพันธ์ระหว่างคลาส (Class Relationships)
* `Medicine` **(1)** ──── **(0..*)** `MedicineLot` : ยาสมุนไพร 1 ชนิดสามารถมีได้หลายล็อต
* `MedicineLot` **(1)** ──── **(0..*)** `RecordTreatmentMedicine` : บันทึกการจ่ายยา 1 รายการอ้างอิงล็อตยาที่ตัดจ่าย
